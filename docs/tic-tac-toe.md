# 动物三连棋 (Animal Tic-Tac-Toe)

一个适合 4 岁儿童的响应式网页小游戏，支持手机、iPad 和电脑。孩子不识字也能基本操作，家里的老人可以轻松陪玩。核心体验：一眼知道点哪里，点击立即有反馈，获胜有温和的音效与庆祝，失利后也愿意继续。

首版只做井字棋，不加入游戏大厅、账号、排行榜、广告、内购、连续签到或复杂奖励系统。

## 一、产品目标

让孩子轻松理解「轮流、连成三个、观察对方」。核心体验：一眼知道点哪里，点击立即有反馈，获胜有温和的音效与庆祝，失利后也愿意继续。

## 二、游戏规则与模式

标准 3×3 棋盘：

- 双方轮流在空格放一个棋子。
- 横、竖、斜任意三个相同棋子连成一线即获胜。
- 棋盘填满且无人获胜则为平局。
- 已占用的格子不能覆盖，结束后不能继续落子。

使用「小猫」和「机器人」作为双方角色，棋子同时有明确的形状区别：小猫圆形底座、机器人方形底座，不只依靠颜色区分。

两个入口：

1. 「和机器人玩」：孩子与本地电脑对手下棋，默认主入口。
2. 「和家人玩」：同一台设备两人轮流操作。

## 三、首次教学

第一次开始时提供可跳过的互动教学，控制在三步以内：

1. 展示两个小猫棋子，让孩子点一下补成三个。
2. 用连线突出三个棋子，展示「三个连起来啦！」。
3. 进入正式对局，用角色头像和轻微呼吸动画提示轮到谁。

教学不依赖长文字，不要求儿童阅读规则。示范布局必须确保只有一个目标空格，避免歧义。设置中可以重看教学。

## 四、界面与视觉

温暖、简洁的绘本风格：

- 奶油色背景，少量柔和的绿、橙或蓝色作为辅助色。
- 棋盘是视觉中心，角色可爱但不要堆满装饰。
- 优先使用自制 SVG，避免依赖跨设备外观差异很大的 emoji。
- 空格看起来像可以点击的小软垫，棋子轮廓清楚。
- 正文与背景保持清晰对比，避免浅色文字。
- 一个页面最多保留一个明显的主操作。

首页仅包含游戏名、角色和两个开始按钮。

对局页包含：

- 顶部：返回、声音开关。
- 棋盘上方：当前角色头像，以及简短提示「轮到小猫啦」。
- 中间：大号九宫格。
- 底部：一个「提示」按钮。
- 家长设置放在首页次级入口，不占用棋盘空间。

## 五、触摸和鼠标交互

- 全格可点击，不要求点中格子中心。
- 主按钮点击区域至少 56×56 CSS px；棋盘格在空间允许时至少 80×80 CSS px。
- 点击按下时提供轻微缩放或颜色反馈，松手后才落子。
- 手指按下后滑出格子再松开，应取消本次落子。
- 不使用拖拽、双击、长按或 hover 作为必需操作。
- 快速连点、多指触摸不能导致重复落子或跳过回合。
- 点已占用的格子只做轻微视觉反馈，不播放刺耳错误音。
- 电脑思考时显示机器人的轻微思考动画，暂时禁止孩子落子。
- 返回首页时，如果本局尚未结束，使用两个大按钮确认「继续玩／离开」，避免误触丢失对局。

## 六、电脑对手与提示

家长设置里是一个**难度三选一**（简单 / 中等 / 复杂），每档捆绑棋盘、几连和电脑策略，避免出现「4×4 三连」这种先手必胜的退化组合：

- **简单**：3×3 · 三连，电脑随机落子。经典入门。
- **中等**：4×4 · 四连，电脑 1 步攻防（能赢就赢 → 否则挡一步 → 否则随机）。
- **复杂**：4×4 · 四连，电脑用深度 minimax（alpha-beta 剪枝，约 4 层），能识破「双威胁/叉」。

设计依据：`几连 = 棋盘边长` 才是平衡游戏（3×3 三连、4×4 四连在双方最优下都是平局）；一旦「几连 < 边长」（如 4×4 三连）就是先手必胜，后手防不住。电脑策略分 `random` / `oneply` / `minimax` 三档，全部由 `engine.js` 的 `createGame(size, winLength)` 提供：`winLines` 按尺寸生成线段，`winner`/`status`/`computerMove`/`hint` 基于这些线段，minimax 用 `heuristic` 静态评估 + `orderedMoves` 走法排序加速。

电脑落子前等待约 600～900ms，让孩子看清轮流过程。

提示功能：

- 由孩子主动点击，不频繁自动弹出。
- 优先提示一步能赢的位置，其次提示需要阻挡的位置，其他情况提示一个合理空格。
- 只用柔和光圈标出位置，不替孩子落子，也不扣分。

## 七、音效与动画

声音可一键关闭，并记住选择。默认不播放背景音乐。

音效包括：

- 成功落子：轻柔的「啵」声。
- 孩子获胜：约 1～2 秒的明亮短旋律。
- 平局：轻快的结束提示。
- 电脑获胜：温和的中性结束音，不使用失败警报或嘲笑声。

音效通过 Web Audio API 合成，避免依赖外部音频资源。必须在用户首次点击开始后初始化或恢复音频；兼容 iOS Safari 的音频限制。音频不可用时，游戏仍完整可玩。

动画要求：

- 棋子落下后轻轻弹一下，约 150～250ms。
- 获胜时逐个点亮连成一线的棋子，再画出连接线。
- 播放少量星星或纸屑，约 1 秒结束，不遮挡棋盘。
- 庆祝动画期间不阻塞「再玩一次」。
- 支持 prefers-reduced-motion，减少动态效果。
- 不使用持续闪烁、剧烈抖动或无限循环庆祝。

## 八、结束反馈

先让孩子看清胜利连线，再在棋盘下方出现结果与按钮，避免弹窗立即盖住棋盘。

文案：

- 孩子获胜：「三个连起来啦！」
- 家人模式：「小猫赢啦！」或「机器人赢啦！」
- 电脑获胜：「机器人连成三个啦，再试一次吧！」
- 平局：「棋盘满啦，这次平手！」

提供主按钮「再玩一次」、次按钮「回首页」。不自动开始下一局。单人模式默认孩子先手；家人模式每局交替先手，并明确显示当前角色。

## 九、跨设备要求

- 手机竖屏：棋盘和主要操作尽量一屏显示。
- iPad：适当放大棋盘，设置最大宽度，避免九个格子占满整屏。
- 电脑：棋盘居中，不拉伸成宽屏布局。
- 横屏或高度较小时允许合理重排和滚动，不能裁掉按钮。
- 适配安全区域、动态视口和设备旋转。
- 禁止棋盘文字被误选中，但不要全局禁用浏览器缩放。
- 支持键盘 Tab 导航及 Enter/Space 落子，提供清晰焦点样式。
- 格子有可访问名称，例如「第 1 行第 2 列，空格／小猫」。
- 回合和结果通过适度的 aria-live 提示。

## 十、实现要求

沿用现有技术栈（纯 HTML、CSS、ES modules，无第三方运行依赖，Node 20+）：

- 将胜负判断、合法落子、电脑策略与 UI 分离（`engine.js`）。
- 明确管理教学、孩子回合、电脑回合、已结束等状态。
- 返回首页、重新开始或组件卸载时，取消旧的电脑落子定时器和动画回调，防止新棋盘出现「幽灵落子」。
- 本地保存声音偏好、难度和是否完成教学即可，不收集个人信息。
- 不需要服务器或外部 AI 接口。
- 优先使用 CSS 和 SVG，避免为了简单动效引入大型依赖。

## 十一、验收标准

1. 横、竖、两条对角线的胜负判断正确。
2. 最后一格既填满又获胜时，显示获胜而不是平局。
3. 已占格、电脑回合和结束后都无法非法落子。
4. 连续快速点击不会放入多个棋子。
5. 电脑等待时退出或重新开始，不会影响下一局。
6. 关闭声音后所有音效立即停止，刷新后保留设置。
7. 音频被浏览器阻止时，界面无错误且游戏可正常完成。
8. 在窄屏手机、iPad 横竖屏和桌面布局下，主要操作可见且容易点击。
9. 不识字的孩子经过一次简短示范，可以完成落子和重新开始。
10. 孩子获胜时既能听到庆祝音效，也能清楚看到哪三个棋子连成一线。

## 交付

```sh
npm run dev            # Vite 完整项目，游戏目录 /game/，井字棋入口 /game/tictactoe/
npm run dev:candy      # 独立静态服务器（同样服务 /game/tictactoe/）
npm test               # node --test，覆盖 engine.js 的胜负/合法落子/AI/提示逻辑
npm run build          # 构建原应用 + 游戏，public/game/ 原样拷贝到 dist/game/
```

文件结构：

- `public/game/tictactoe/index.html` — 页面与语义结构
- `public/game/tictactoe/style.css` — 绘本风格、响应式与动画
- `public/game/tictactoe/app.js` — 状态机、交互与渲染
- `public/game/tictactoe/engine.js` — 纯逻辑：胜负判断、合法落子、电脑策略、提示
- `public/game/tictactoe/sound.js` — Web Audio 合成音效
- `public/game/tictactoe/art.js` — 自制 SVG 小猫/机器人
- `tests/tictactoe.test.js` — 逻辑单元测试

同一 Wi-Fi 下的 Pad 可访问 `http://电脑局域网IP:5173/game/tictactoe/`，需要系统允许本地服务网络访问。
